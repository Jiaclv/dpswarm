# 实验运行器与冻结记录

这里保留 DPswarm 的历史比较运行器、分析脚本、测试和冻结配置。它们是研究工具，依赖各批次的模型接口、预算及评分环境，不是 DSH 插件的安装步骤。

| 目录 | 用途 |
|---|---|
| `swe_fixed_team_20260903/` | 固定团队 SWE 比较与控制边界 |
| `swe_verified_20260903/` | SWE 传输、评测与验收辅助工具 |
| `big_budget_team_20260906/` | 预算与协作角色对照 |
| `mechanism_ablation_20260906/` | 机制消融与上下文管理对照 |
| `lg_compare_20260910/` | 两种编排实现的并行／串行比较 |

可直接阅读与复算的发布数据见 [实验报告索引](../reports/README.md)。调用统计、冻结 gate 和计划中的设计约束有复核价值；它们不自动授权新的运行，也不证明当前版本效果。

真实实验需要自行提供凭据、评分环境与预算，并可能产生费用。凭据使用环境变量或已忽略的本地配置文件。部分旧分析脚本依赖未公开的原始归档；原始模型产物、运行目录、进度日志和锁文件不随仓库发布。`lg_compare_20260910/logs*/` 保留调用元数据，完整 `runs*/` 仅在本地归档。

不要批量删除 `validation/`：其中也包含有效脚本、测试与准入数据。修改准入时必须保留拒绝与审计语义，不能用删除旧 gate 的方式绕过检查。

## 冻结准入证据

`swe_fixed_team_20260903/validation/gate_revision12_test_evidence_20260905.json` 对验证文档、核验脚本和四份 JUnit 证据逐字节绑定。这些文件保留原字节，包括历史来源标识；它们属于必要输入，与可丢弃的测试输出不同。其他冻结实验计划也按原始版本保留。

该目录的 `verify_boundaries.py` 是生成历史证据的核验工具，需要当时的根机制文档、批准提案和原始归档；仅克隆公开仓库不具备这些输入。不要替换成新的架构文档来伪造旧哈希。当前产品和默认离线 CI 不依赖这些私有文档；运行器验证已有 gate 时使用公开的冻结证据文件。
