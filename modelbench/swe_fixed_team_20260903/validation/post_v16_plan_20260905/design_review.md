## 2. 固定对照条件与成分归因

### 角色实验使用预先固定的 anchor，不选择 P2 的表面赢家

建议 P3/P4 的机制 anchor 固定为 **F1 OFF、F2=4096、F5 OFF、CM pool=12、装配 OFF、600k token / 28 工作调用、每 worker 8 次工作调用**；Lead 与 worker 共享预算，closing/CM 的账本口径固定。三项关闭/保留是预先选择的比较基准，不声称它已被证实最佳。Solo 与 Team 都用同一 anchor，避免再次发生 Solo F5 ON、Team F5 OFF 的隐性混杂。

如果后续决定根据 P2 选择另一组合，应在看结果前冻结选择规则及候选集合；选中后另开全新重复进行比较。探索数据只能用于选择，不能同时当作选中机制的独立确认。不能默认选成功率最大格，也不能用相同数据为“赢家”计算未调整的确认 p 值。

当前总 PLAN.md 的 CM 模型/阈值描述属于旧阶段，不能未经核对沿用。新 manifest 必须逐项冻结实际有效的 CM 模型、provider、thinking、context_budget、keep_recent、max_tokens、pool、装配开关和 F1/F5 条件。若使用 post-v16 anchor，应明确列出当前的 DeepSeek-v4-Flash、12,000 估算上下文阈值、keep_recent=4、thinking disabled，而非把旧文档的 GLM-Flash/24,000 当成当前实现。

### P2 应估计什么

F1×F2×F5 完整 2×2×2 是最小的无混淆三因素矩阵。少做若干角点只适合筛选，无法把主效应与交互拆开。F2 的两个水平只改变 CM 输出硬上限，摘要目标长度、CM 模型和压缩触发保持相同。F1/F5 必须使用修复后、含真实文件/采用进展的统一状态定义，不能让一个 arm 用命令正则、另一个 arm 用文件证据。

主要效果是按计划分配的 **全部 run** 的 official resolution 差异；首次真实写入、CM 截断、是否仍有 CM 配额、验证覆盖、非空 delta 未采用属于次要机制读数。F1 从编辑后才可能生效：即使实际触发次数为 0，仍保留所有该 arm run 的分母。可以说“此配置很少暴露于目标分支”，不能只抽取已编辑、通过或出现 curfew skip 的 run 来估计 F1 效果。

P2 的因子主效应预先定义为在另两因子所有水平及三题等权平均后的差；交互如 F1×F5 也预先列出。若仅需探索，则报告效果与区间、不加显著性标签；若要作三个主效应的确认检验，必须预先定义检验族并调整多重比较，不能只检验显著的那一个。轨迹签名可以支持解释，不构成单独的干预归因。

### P3/P4 应估计什么

首要角色对比为 TG−GT：两边使用相同模型集合，只改变实现与测试职责的分配。它识别的是固定 Lead、提示、工具和预算下的职责匹配差异，不是两个模型的通用智力排名。TT/GG 用于区分“异构”与“某个强 worker 加入”的混杂；可预写异构对同质对比为 `(TG+GT−TT−GG)/2`，同时给出四格原始计数，不能只呈现平均数。

家族对比预写 TL−LT 与 GF−FG。其 2×2 对应矩阵必须有同期 TT/LL 与 GG/FF。完整覆盖的范围是 **Terra/Luna** 和 **GLM-5.3/GLM-5.3-Flash** 两对；没有测试 GPT-5.6-Sol 作为 worker，也没有遍历 5×5 所有跨家族组合，不得称“GPT 全家族完整排名”。Lead 始终 GPT-5.6-Sol，不能据此声称 GLM Lead、自动组队或动态路由有效。

P4 必须新增当期 TT/GG；若使用一体 P3-full，所有 11 格在同一冻结区组内交错即可。重复旧 TT/GG 与当前锚点的差异本身单列为阶段漂移诊断，不能把旧样本简单加进当前样本量。

## 3. 工程 gate 与互斥停止规则

P0/P1 是工程可用性门禁，**不以通过多少 SWE 任务为门槛**。需直接覆盖已知问题：声明与可用工具一致（含 scout）、正确区分写入尝试和真实非空 delta、Lead 采用后的编辑进展、并发 budget 文件替换、worker_error 上报、CM 账本、closing 的 reserve 边界、取消/排空及 usage 缺失。F3 最后两次调用的边界应先用确定性离线场景触发；不能要求靠真实模型恰好碰到该状态才算工程验证。

P1 的 6 个 run 不覆盖 Luna/Flash 的全部真实调用路径；新增模型进入 P4/P3-full 前，应检查其已有真实协议证据能否适用于新 revision，缺口需单列小范围通道验证额度。不得把某个模型特有的解析或工具不兼容当成该模型能力排名。

按以下优先级处理，同一次检查只能进入一个状态：

| 优先级 / 状态 | 触发条件 | 下一步 |
|---|---|---|
| 1 STOP_USER | 用户取消或明确停止；必须立即生效的隔离/安全边界破坏 | 不再准入；按既定取消/收束契约结束已在途调用；保存账本，不自动继续 |
| 2 HOLD_ENGINEERING | 冻结源码/参数/计划哈希漂移；已声明工具不可用；本地 worker/runtime 故障；grader 无法评分；未知/悬空用量；无法由合法预算/候选终止解释的预定 worker 漏启动；美元准入不可证实 | 停止新的区组；先收束并审计，不能用新调用掩盖未知费用；修复需新 revision、新门禁与单独计划差异 |
| 3 CONTINUE_CANDIDATE | 工程记录有效，但 unresolved、空补丁、写入脚本失败、正确暴露工具下的模型非法动作、正常 token/call/USD 限额停止、worker 因候选行为 blocked | 保留为该 arm 的真实结果，继续原定固定样本量；若合法预算使完整策略无法完成其预定 worker/候选，按预写的策略预算失败处理，不删除该 episode；不得作为提前停掉弱模型的工程理由 |
| 4 COMPLETE_STAGE | 预定全部区组完成且账本/评分状态明确 | 封存该阶段，按预写统计规则分析；后续阶段是否开展另行决定 |

“已声明的工具在工程上不可用”与“模型请求了一个不允许的工具”必须在 gate 前写成机器可判定的不同类别。不能看了 official 成败后再决定某个错误算基础设施还是模型。

工程停止留下的所有已开始 attempt、费用和缺失结果继续公开。未评分记 unknown，不能悄悄记为 0 成本、静默删除或反复重试至通过。若修复改变协议，不拼接修复前后样本；新比较须包含同 revision 的全部对照臂，原故障批单列。没有完整可比样本时只报告结果边界，不能以过滤后的成功子集作确认结论。

阶段结束的结论标签与工程状态分开：达到预先定义的统计/实用性标准才称“支持该有限命题”；置信范围仍同时容许有用收益和无收益则为“不确定”；明显不满足实用标准则“当前方案不进入推广”。普通全失败不是工程 HOLD，也不是普遍机制证伪。不能同时写“P2 失败转预算”又写“只有全灭才能转预算”：P6 是独立问题，入口只有工程可用、政策冻结和后续执行授权。

依赖关系：P2/P3 依赖 P0/P1 及自己的冻结配置，不依赖另一阶段取得正结果；P4 依赖家族 scope 预选与新模型通道可用；P5 依赖装配工具问题修复及新同期 ON/OFF；P6 依赖预算准入/状态阈值定义完成；P7 依赖美元池可实施、选择器非 oracle；P8 依赖完整策略与未接触任务名单冻结。每个可选阶段有自己的固定 N、上限和 HOLD 状态，不能用另一个阶段的“成功”自动解锁支出。

## 4. 随机化、重复单位与统计口径

**一个任务是外推的基本单位；一个新会话、新容器的完整 run/episode 是同题重复。** Worker、API call、两个独立候选、多个测试用例都不是新增任务样本。六题×三次不是 18 道题；30 题×两次不是 60 道独立任务。所有模型调用保留 role、worker ordinal、requested/observed settings，统计归属回 run/episode。

每个 task×repeat 为一个区组，区组内包含该阶段所有 arm。执行前固定随机种子并导出完整排程；对 arm 的运行顺序及并行槽位作平衡随机轮换。同臂重复不要总是彼此并行；三次重复尽量分布在不同轮次。模型 session、候选仓库和产物隔离，候选不读取其他 arm 的补丁或评分。不要把同一两两并行组合永久绑定到同一模型，否则机器资源/时段与 arm 共线。

默认采用单 run 依次执行以减少资源干扰；如实际选择两 run 并行，必须固定全局模型/容器槽并预先平衡并行搭档，墙钟需同时报告排队/推理/评分边界。费用比较以统一估价表为主，另报告按实际时刻的价格敏感性；不能让高峰/低峰恰好只落在某个模型。

每阶段必须先写 estimand 与主比较：每任务内先对重复平均，再按任务等权汇总。主指标为完整策略的 official resolution；成本和时延是同一完整单元的总量。可以同时给“每成功所需总成本=全部 episode 费用/成功数”，若 0 成功则未定义/无限，不使用成功样本的平均费用替代。无条件均费包括失败、超时、CM、重试和选择器；不可按通过/双 worker 完成/已编辑/有 patch 过滤后重新排名。

单格 n=3 的 Wilson 95% 区间很宽：0/3 约 [0,0.562]，3/3 约 [0.439,1]。因此开发矩阵即使出现 3/3 对 0/3，也首先是值得确认的方向，不能将全部格的最强差异宣布成稳定模型排名。不同条件重复同一题的依赖，不由简单合并的 Wilson 区间解决。

开发阶段以逐题计数、任务等权效果、费用/时间范围和机制读数为主；六个任务不足以支持很精细的总体区间。P8 使用任务为 cluster 的成对分析/重采样，保留每个任务的全部策略及两次重复；不要把 180 个 episode 当作 180 个独立任务。若分层抽样，分析权重和重采样层级随抽样方案预先固定。小样本或离散分布下不要只报告正态近似 p 值。

P8 建议主比较固定为 Team−Solo一次、Team−Solo双候选两个同预算差；用 Holm 控制这两个主比较的检验族，或预写一个主比较、另一个明确为次要。不得看完结果后只保留有利比较。排序、具体失败模式及 Solo双候选−Solo一次可作次要分析，明确其探索属性。

固定 N，除工程/用户停止外不按中途成功率、置信区间或显著性可选停止。若希望成本优先的序贯设计，必须在首个付费调用前另行冻结观测点、alpha spending/有效区间及 futility 规则，不能把每几个 run 看一次图临时当成序贯设计。达到阶段上限但不确定，就报告不确定；后加样本属于新计划、新证据。

## 5. 预算阶梯与同美元策略的关键定义

P6 四格必须全部保留：600k/28、900k/28、600k/40、900k/40。同一个政策内比较 900k−600k 时固定调用数；比较 40−28 时固定 token；对角线差是联合变化，不是单一成分。Solo 与 Team 使用相同全局限额口径，worker_calls 固定，CM 是否另有调用池以及其 token 仍计入共享额度写清楚。

优先沿用 F5 OFF anchor。如果另一个计划决定保留 F5，P6 要么固定绝对触发 token 阈值，要么将“随预算比例变化的反馈阈值”明确纳入预算政策的定义，不能再称纯 token 额度效果。绝对阈值如尚无可配置实现，属于待工程实现要求，不能假装现有 flag 已支持。

**同美元指相同的 API 等价准入预算上限，不是实际已花费金额相等。** 冻结计价货币、汇率、缓存规则、reasoning 是否含于输出、GPT 请求/实际档位边界、DeepSeek 统一比较费率与历史时段敏感性。不能按一次实验结束后的总费筛选成“同美元组”，也不能事后截掉超额调用来伪造预算约束。

P7 的三个策略必须是完整可执行政策：

1. Solo 一次：一个独立修复轨迹、共享的预算/安全限额。
2. Solo 两候选：两个独立 session/仓库、无彼此答案和评分泄漏，再由冻结的选择规则选出一个最终补丁；不是看到 official 结果后取 max。
3. 固定 Team：固定 Lead/worker 有序组合、同一已冻结机制；不是按每题历史结果选择最佳模型。

两个候选的额度划分、顺序或并行、提前完成后的剩余预算能否转给另一候选、选择器额度、输入裁剪、选不出来时的 tie-break/失败处理，都须在 prepare 前写死。选择器只可读取允许的候选补丁、问题、公共测试与候选验证信息；不可读 gold/test_patch/F2P/P2P 或 official 评分。若选择器用模型，其 input/cache/output/reasoning/CM/重试均在同一 2 或 4 美元池内，不额外赠送一轮 Lead。

USD gate 必须在调用前可保守预留并在调用后完整结算。当前某些适配器的输出 cap 是请求值而非可强制上限，实际档位也可能未知：若无法给出可信的预留/超额规则，阶段保持 **HOLD_USD**。可以继续离线估价或把实验另标“事后等价费用分析”，不能对外声称已实施严格同美元预算。未知费用不可按零补齐。共同的 token/call/wall 安全上限也要冻结，并报告哪个约束真正绑定；若 USD arm 总先撞到 token 上限，就不能称已有效考察美元约束差异。

## 6. 新任务确认与样本量的诚实边界

在 P8 首个调用前冻结 30 个未接触 task 的完整名单、数据/harness/source/计划哈希。未接触是未用于本项目模型尝试、机制调参、方案选择或失败分析；不是仅没进最终报告。排除全部已见题及其同一 issue 的重复版本。按预先定义的公共元数据随机抽取/分层，例如 repository；不按 gold、官方测试结果或试跑通过率筛选。

可以先冻结一个更大的未打开候选池；只因明确的基建不可运行条件替换时，必须遵守事先固定的替补次序，并保留被替换任务的故障和费用。不能因所有策略失败或不利于 Team 而换题。题目难度标签只能使用执行前的公开元数据，或与该留出集隔离的模型；不能用本次 Solo 成败再把样本分成“适合 Team 的难题”作为确认结论。

P8 在固定 4 美元这一点比较三策略，**不验证整个预算曲线**。30 题×两次是有用的新题检查，但仍可能无法排除小或中等效果；不是 10pp 差异的保证检出设计。确认是“政策、假设与分析事先锁定且使用新数据”，不自动意味着有足够功效或一定得到确定结论。区间仍宽时结论只能停留在有限证据/探索支持，不能用“未显著”宣称等价。

若产品决策要求保证检出某个最小重要差异，例如 10pp，应在 P8 前用开发数据估计任务内相关与任务间变异，围绕预设效应做任务级功效仿真，重新冻结所需任务数及费用上限。仅作量级说明：简单独立的配对二项近似，在不一致率约 0.4、双侧 5%/80% power、目标 10pp 时需要约 300 个独立任务对，而非 30；实际多重比较、重复与异质性应由模拟处理。不能先跑 30，再看到 p 值不够而临时加到显著。

## 7. 冻结、审计与结论模板

prepare 前至少封存：计划全文哈希、task IDs/来源/替补次序、策略与候选选择规则、完整 effective_limits、模型/角色/adapter、requested/observed 字段策略、价格卡/汇率/时区情景、预算划分、随机排程、停止规则、主 estimand/对比族/N、评分隔离规则和输出表结构。计划自身必须绑定到 manifest；不要重现只绑定总 PLAN.md、未绑定实际预注册文本的缺口。gate 文件版本化，已被旧 manifest 引用的文件不得原地覆盖。

每阶段输出：全部 scheduled/started/graded/unknown 与实际 worker 调用覆盖；逐 task×arm×repeat 的官方结果与真实 patch 状态；按角色和 CM 的完整费用/用量；workflow stop 与 official resolve 的交叉表；所有工程 hold/修订/重试的独立记录。对变更参数、未运行分支和未支持的主张明确标注。

允许的结论形式：“在固定协议、六道开发题与每格三次下，观察到某个有序 worker 组合的方向差异；新任务确认在 4 美元预算点支持/未能确定该策略优势。”不允许从同一份结果跳到“异构普遍胜出”“F2/F5 活性成分已证实”“预算等价倍数”“全部困难任务可分辨”“模型稳定排名”。

本审查建议先形成上述互斥范围、有效参数与门禁的最终冻结清单；是否实施工程变更、采用哪个范围、支付任何后续模型费用，仍由后续明确执行授权决定。
