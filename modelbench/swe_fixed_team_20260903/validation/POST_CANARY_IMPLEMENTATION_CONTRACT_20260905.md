# 难题实验后的实现修复合同

本轮依据用户要求：“先把我们机制的实现出现的问题修复；如果需要改动机制，先说明，等审批”。范围限于落实已有状态、观测和冻结声明。测试角色及 Lead 复核要求见根目录[待审批提案](../../../机制改动提案-测试证据-20260905.md)，未实施。

## 结案状态与事实一致

结果继续使用 `schema_version=12`，并以独立 `death_phase_semantics=observed_worktree_delivery_v1` 标识新的结案观测语义；不能仅凭 schema 相同混合旧、新阶段指标。

- 命令尝试继续单列，不再用“命令看起来像写文件”证明文件已修改。
- 新阶段依据真实工作区观测、可读取的保存产物及正式交付/采纳事实。明确未知的证据不能补成 `no_edit`；成功保存非空产物也不能忽略。
- Lead 采纳 Worker 的补丁后，按已有真实观测计入修改；Worker 的阶段优先考虑明确采纳，其次完整非空交付，再考虑实际改动。
- 没有新标记的旧结果保持原有阶段及命令尝试/交付语义，报告与审计明确标识、分组。带新标记的结果必须与观测、交付和采纳证据一致。
- 本变更是观测修复，不改变 F1/F5 输入规则、默认开关、工具准入或语义验收结果。

## 工具输出证据

环境和运行器继续使用既有输出截取范围，新增/保留两条输出流的 `*_truncated`、`*_captured_chars`、`*_returned_chars`。

- 长度使用 Python 字符数，不冒充编码字节数。
- captured 仅指已捕获并保存的文本；触发采集大小上限时，不能从它推断真实完整输出长度，原 `output_limit_exceeded` 仍须保留。
- 运行器二次裁剪时保留原截断事实与 captured 长度，returned 长度对应最终反馈文本。
- 完整捕获日志仍在宿主证据中；输出被裁剪不是命令成功或失败的依据。
- 普通 Bash、`exit_code`、超时和捕获超限语义均保持。`pytest | tail` 的外层状态不能自动当作 pytest 结果，本轮不强制 pipefail，不以输出文本重写状态。

## 执行已声明的放行范围

新检查只落实 gate 已声明的限制，不替 gate 制定新模型、预算或任务选择策略。

- gate 若明确 `live_run_admission=false`，不能因 status 字段为 PASS 就启动。
- 若 gate 声明 allowed_schedule，则核对实例、arm、重复次数及重复条目；requested_roles 核对有序生产/测试角色、Lead 和 CM；effective_limits 与评分输入也须相符。
- 每条实际运行参数须重新计算 effective limits 与配置 hash，完整公开实例和评分合同必须绑定到已冻结的输入/source；不能只核对一份未被执行的哈希表。
- 现有验证材料在建 batch 前核验；运行前重新核对当前与验证快照材料，材料路径限定在对应验证目录内。
- 错误在模型、容器或镜像资源分配前拒绝。未声明这些范围字段的旧 gate 不补造范围；旧结果与冻结快照保持原字节。

## 验证与后续运行

本轮仅离线测试、只读历史审计；新增默认 gate 是 `gate_revision12_post_canary_20260905.json`，状态为 OFFLINE_PASS，不授权真实模型调用。

这次代码变更增加了模型可见的观测元数据，并改变状态字段的解释标记。未来实验必须重新冻结对应源码、输入、配置和验证材料；不能把本次离线测试或原 xarray 成绩当作修复后的真实实验结果。未修改已关闭的 xarray 实验、其问题/补丁/成绩、旧 gate 或机制待决事项。
