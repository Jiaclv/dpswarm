# 0.7.7：Lead 分工提示与实现者返工

本版将必要修复交回实现者：Lead 理解原任务、分工、提出具体缺陷并验收，实现者负责写代码和修改。角色职责主要通过 prompt 约束；没有新增全面禁止 Lead 写文件的门禁，也没有给 Lead 添加累计预算。

## 用户确认的规则

- 首次 worker 仍严格遵循现有手动／Auto／不限制设置。
- **返工不设累计 token 和调用次数上限，不扣首次 worker 剩余额度**。Lead 针对未满足的原要求继续交回实现者，满足要求后停止。用户取消、已设置的角色超时和实际模型故障仍按原流程处理。
- 模型与推理强度沿用原实现者；每次返工建立来源关联，首次和各轮的实际／未知用量、CM、报告与交付分别保留。
- 子 worker 不再收到 Lead 的“先查团队、再派发团队”指令。Auto 首轮预算提示计入完整请求历史与缓存输入，参考值不代替 Lead 决策。
- 失败前保存的文件不是已提交的交付包；不会因 Lead 后来改好，就反向把失败 worker 标成验收通过。

## 当前边界

这证明返工链路及提示注入可用，**不证明真实模型一定遵守分工，也不证明质量提升或节省成本**。返工目前支持同一宿主进程里的当前用户任务；重启后历史记录仍在，但返工恢复明确返回 `REWORK_RESTORE_REQUIRED`，不会猜测旧授权。已验收的交付不能回退返工；返工不自动重跑测试者或 Reviewer，Lead 需按原允许范围检查修改。

本机日常 DPH 已在空闲时升级到 0.7.7 并恢复运行：51 份 JS／Python 安装源码逐项一致，插件版本正确，13 个设置分组与历史状态保持一致，原实验侧车未停止。详见 [DEPLOYMENT.json](DEPLOYMENT.json)。历史实验和作品未重跑或改写。
