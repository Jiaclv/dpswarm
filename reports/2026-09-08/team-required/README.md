# 插件 0.7.4：显式团队与用户预算

修复的实际问题：用户打开团队后，Lead 读取了 `enabled:true`，仍以“任务简单／不需要测试”为由直接写文件。0.7.4 增加宿主工作流检查：派发固定团队前允许只读文件调查，拒绝 Lead 写入、命令执行和另开子 agent；Code Mode SDK 同样经过检查。纯文本跳过只提醒一次，持续拒绝则明确报错。

预算决定权与团队强制开关独立：

| 模式 | 谁决定每个 worker 的额度 | 运行行为 |
|---|---|---|
| 手动 | 用户 | 原样冻结已保存的 token／调用上限，Lead 不能改值、倍增或重新分配；上限不要求用满 |
| Auto | 当前 Lead | 读取任务后，给每个启用角色明确数值与理由；没有隐藏评估模型 |
| 不限制 | 用户选择不加限额 | 不加累计 token／调用上限，保留的旧手动值不生效 |

这些是独立 worker 额度，不是团队共享池，也不限制 Lead 主对话。若模型预检期间设置变化，在启动子角色前明确报 `WORKER_BUDGET_SETTINGS_CHANGED`；本次团队启动后继续使用已冻结值。CM 与角色模型选择保持独立。

## 执行与恢复边界

任务绑定使用 root session、原始用户消息 ID 与内容哈希，压缩摘要和技能注入不替换任务。Fork 不继承父任务的满足状态。显式开启的会话收到新用户任务后重新要求团队；开关关闭则走普通宿主流程。

只有宿主真实创建并绑定子会话、且团队流程安全返回后，才允许 Lead 接管。单纯调用 status、冻结预算或失败于零子角色预检都不算团队执行。子会话绑定不等于模型已调用，更不等于任务成功。并发的第二次启动不能结算第一次；物理清理不确定时保持限制。冷恢复必须核对旧宿主已退出、原 run 与全部子会话、控制面终态及零活动槽位；缺证据不放行。

这是工作流可靠性验证，不是文件系统安全隔离，也不证明外部服务商可用、动画更好、团队净收益或 CM 净收益。正在运行的历史实验保留冻结版本，日常宿主的安装与重启独立记录；本文不把“验证通过”写成“在线环境已升级”。
