# 模型选择器空列表修复（2026-09-11）

用户现象：选择“测试者模型”时显示 0 个选项，并同时提示“当前宿主未提供模型目录”和“先到设置完成配置”。

## 已确认原因

本机全局 DSH 为 0.1.5-rc.1，Web profile 的 DPswarm 包版本为 0.9.7。实际安装的浏览器文件在插件 apply 阶段缓存模型接口；typed Remote 的 remote.session 稍后就绪时，选择器不会重新获取接口。因此，该提示不能作为“用户未配置模型”的依据。

源码中的早期兼容处理也存在三个可复现问题：空的 legacy llm 对象遮挡后来就绪的 typed Remote；条件注入捕获已卸载的服务；legacy connection.api 后挂载未被重新读取。真实 Cordis 回归复现了这些问题。Cordis 的公开 ctx.get() 不要求 inject，不能把故障归因为点号服务名无法读取。

## 修复与安装范围

- 每次读取目录时，通过公开 ctx.get('remote.session') 获取当前模型目录服务，缺失时检查当前 connection.api.llm.models。
- 保存配置时重新获取当前 settings 服务，保留本机连接、可写快照、版本与宿主确认检查。
- 目录读取失败显示“暂时无法读取模型”，避免误导用户重新配置模型。
- 更新了源码与 README；本机仅原子替换 Web profile 已安装包的 lib/client.js。包版本仍为 0.9.7，未将其他未提交的后端改动整包安装。
- 未调用外部模型，未修改实际模型配置、凭据或任务开关，未重启或终止宿主任务。

安装文件：`%USERPROFILE%\.dsh\profiles\web\node_modules\dpswarm-dsh-plugin\lib\client.js`

源码与安装文件 SHA-256：`A96AC5227B7139CF6961022D094905F2D0247EDBA905A4DA6F89B889493B0BD2`

## 使用与验证边界

请刷新整个 DPH 网页，再进入“设置 → DPswarm → 模型分工 → 测试者模型”，必要时点击“刷新列表”。本机宿主默认加载 client-hmr，资源变更由其重新发布；本轮未直接进入用户已登录页面确认列表内容。对宿主根页面的独立读取返回登录要求，因此没有把隔离浏览器结果标为真实登录页面已验收。
