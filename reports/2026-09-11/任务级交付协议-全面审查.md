## 逐条清单结论

### 1. outcome 由 mandatory 需求验证决定？—— **Closed**（一处设计边界记 O1）

集成门路径（`_try_finalize`，dpswarm/orchestrator.py:149）真实成立：

- success 要求 `integrated == "pass"` **且** mandatory 无 fail 无 unknown（orchestrator.py:223）；fail/unknown 由 `_req_statuses` 逐需求归一（:253），未提及的登记需求强制 unknown（:268 `st or ("unknown" if per else default)`）。
- partial 要求"有验证子集"：gaps 挂账后 Lead 再收束时 `passed = mandatory 中 status==pass`，空则 failed（:203-216）。
- 探索性失败的判定边界：**终态非 accepted 的 item 不进候选集**（`_assemble_candidate` 只收 `accepted_items`），集成验收只看已验收交付 + 登记表。代码侧兜底：mandatory 无交付支撑时 LLM 不提即 unknown → 阻止 success。测试 ③（test_finalize_protocol.py:106）锚定：escalated 探索分支在场仍 success，`accepted=2, total=3` 落账正确。
- **边界**：仍有一条按 item 计数的路径——`_finalize_run` 回填（orchestrator.py:641）：degenerate/escalate/quota/轮次耗尽等**未过集成门**的终局，按 `accepted>0 → partial` 直接推导（:666-671），无逐需求验证背书。代码注释已声明"保守 partial"；这些 item 过了 Lead 单件验收，可视作弱意义验证子集。**判为设计边界（O1），非实现错误。**

### 2. mandatory 只增不减 / covers 重声明校验？—— **Closed**（两点残留记 O3/O6）

- 覆盖门真实拦截：`_dispatch`（orchestrator.py:798-819）covers 并集缺漏 → `coverage_gap` 审计 + `coverage-rejected` 动作 + **不建队**（return [] 在 create_work_item 之前），Lead 下轮重选。测试锚定（test_closure_and_remap.py:170 断言首轮零建队）。
- **首轮少登记绕行不存在**：登记表由代码从父任务原文推导（`build_requirement_registry`，orchestrator.py:1532），Lead 无法影响登记内容。lead prompt 只声明 covers 义务。
- 修复轮豁免（`has_accepted` 跳过整门）是刻意设计（r6 实证误伤回归测试在 :218）；豁免期间弱化 mandatory 不被拦，但**集成门仍是终局正确性闸门**——豁免买不通 success。覆盖门是 fail-fast 效率门，集成门是正确性门，分层成立。
- 残留 O3：集成验收"以原文为准"只靠 prompt 契约 + `integrated` 总 verdict 承载；LLM 对**登记表外**需求的逐条 verdict 在 `_req_statuses` 被丢弃（只回表 registry id）。
- 残留 O6：`weakened`（只增不减）校验在数学上被 `missing`（全覆盖）蕴含——missing 空 ⇒ weakened 必空，铁律独立校验点是从不单独触发的冗余。无害：门若未来放松它即成防线。不改。

### 3. finalize 幂等跨进程？漂移剔除？—— **Fixed**

- **原实现只在内存**：`_finalized` 是 Orchestrator 实例属性。探针实证（artifacts/test-tmp/review_probes_20260911.py）：同 store 重建控制面重跑 run_task → **2 条 run_finalized + 2 条 candidate_assembled**，且重烧一次集成验收 LLM 调用；single 路径重跑更糟（对已 accepted 的 root 再 submit 直接撞不变量）。
- **修复**：`_close_dimensions` 的 run_finalized payload 增 `final`/`contract_version`；新增 `_resume_finalized`（orchestrator.py:337）挂到**两臂** run_task 入口——同任务（contract_version 匹配）重跑 → 回填已落账三维度与候选标识直接收口（`already-finalized` 动作），不重复验收/装配/落账；`_finalize_run` 配套：终态相位跳过封存（不留伪 seal_error）、economics 去重。**合同键控**是关键安全边界：server.py:373 每请求新建 Orchestrator 共享 cp，若无键控，第二个不同任务会被第一个任务的终局劫持。
- 进程内 `_finalized` 缓存同步加合同键控（`_try_finalize` 顶部，:163）。
- 漂移剔除（验 A 封 B）：逻辑正确——accepted 事件的 `package_id`（control.py:752 落账）与 item 当前 `submission_package_id` 比对，不一致剔除 + `candidate_version_mismatch` 审计；正常流程中终态不可再迁移使漂移只能靠越权改写，防御纵深定位准确。测试 ⑦ 锚定。

### 4. 验收保真：超限后 L1+ref 真的够吗？unknown 语义一致？—— **Closed**（限价记 O4）

- 2000 硬截断确已取消：≤12000 全文进验收（`_review_material`，orchestrator.py:1405）；测试 ⑥ 证明 2000 之后的缺陷可见。
- >12000：L1 逐字段（确定性提取，cap=8000）+ 全文 ref + "材料缺失处不得臆断，记 unknown"明示。**纯散文缺陷在 12000 之后仍不可见**——这是窗口机制的固有限价，由 unknown 纪律兜底。
- unknown 语义一致：per-item 验收 uncertain → 修 context 重试（不否决 item 直至预算耗尽）；集成验收 unknown → 阻止 success、Lead 续决策、再收束落 partial（不否决 run）。测试 ① 锚定。
- 残留 O4：ref（submission_package id）对验收方**不可取回**——Lead 没有 PULL/fetch 通道，ref 只是审计指针；真正的保真依赖 unknown 纪律。per-item uncertain 重试不解决超窗（材料同样截断），靠 max_attempts 兜底上交。

### 5. uncertain/invalid_output 分维误判？—— **Closed**

`_attribution`（orchestrator.py:1492）对四分支合法值直接 `RejectAttribution(raw)` 构造成功，**不存在误判路径**；INVALID_OUTPUT 只接管缺省/None/非法字符串，UNCERTAIN 是显式新值。`escalation_path`（levels.py:42-43）六值齐备无 KeyError 风险。test_orchestrator_fixes.py 两条回退测试已同步更新措辞。

### 6. 8 条反例锚定语义还是实现细节？—— **Closed**（⑧ 断言收紧）

逐条读过：mock 只提供**裁决输入**（Lead verdict 文本），断言全部落在**系统计算的输出**上（outcome 三维度、run_finalized/integration_review 审计事件、prompt 内容可见性）——不是 mock 回声。① unknown→partial、② 接口不兼容→不 success、③ 探索失败不否决、④ 无验证子集→failed、⑤ budget→partial+budget_exhausted、⑥ 2000 后缺陷可见、⑦ 漂移剔除、⑧ 幂等，语义锚定成立。
唯一弱点：⑧ 原断言 `digest 相等 or candidate 不在` 的 or 子句虚软——**已收紧为严格相等**（缓存本就含候选）。

### 7. LangGraph 层并行与通道纪律？—— **Fixed**（三处竞态）

- **通道纪律成立**：`done`/`executed` 是 operator.add reducer 通道，并行 worker/review 写安全；`turn/action/decision/final/wave/pending/deferred` 每 superstep 单写者；`p` 是 Send 瞬态载荷从不回写。无 reducer 冲突风险。barrier 测试证明真并行（test_orchestrator_lg.py:113）。
- **控制面线程安全成立**：`_transact`/`_record` 均过 `_lock`，EventStore 有 seq 连续性防线（TXN_SEQ_GAP）+ 写者文件锁。账本单写者串行链在并行验收下不变。
- **发现并修复三处并行面竞态**（LG 并行验收把 `_review` 从串行循环变成多线程，放大了既有隐患）：
  1. `lead_tokens +=` 读-改-写非原子（并行验收下 §6 内存计数可少计）→ 加 `_lead_tokens_lock`（orchestrator.py:98；4 处增量点全包）。
  2. `prepare_package` 的 `assembler.compress_fn` 按次注入/还原是**属性级竞态**：并行修-context 重试交错会串号（成本错记他 item）甚至残留 lambda → `_assemble_lock` 串行化注入/装配/还原段（:460-470）。
  3. `_pull_respond` 裸迭代 `_submissions`：并行 worker submit 时 dict 伸缩可抛 RuntimeError（**两臂同病**，父类 ThreadPoolExecutor 同样并发）→ 快照迭代（:1086-1089）。

### 8. 全量一般性审查（逻辑/边界/异常路径/审计泄漏）—— **Fixed**（三处）

1. **F2 stop_reason 透传断裂**：autoclose 零 accepted 分支硬编码 `stop="completed"`，与 `_finalize_run` 回填的 quota/rate-limit 透传映射自相矛盾——同一终局两种 stop_reason。探针实证（final=quota-exhausted 却 stop_reason=completed）。修复为原因透传（quota_exhausted/rate_limit_exhausted/budget_exhausted），orchestrator.py:180-183。
2. **F-audit 审计不对称**：`integration_review` 只在 fail 落账——"outcome 由 mandatory 验证决定"的**通过侧证据从不在账**，success 无法被事后复核。修复：all_pass 分支同样落逐需求 statuses（:226-229），fail-closed/version-drift 路径亦有据可查。
3. **F1 single/split-assistant 交付面无截断阶梯**：`_run_single` 半截交付会被直接 submit+accept 封存为 root 终局交付（探针实证：无 max_tokens_escalated、半截文本入 result）。修复：single 面走 `_complete_ladder(surface="single")`；split 协助者回报面（同构交付面）走 `_complete_worker_ladder`。
4. invariants 一致性核对通过：autoclose 的 root escalate 走 `(None, ESCALATED)` 合法转换（invariants.py:72）；新事件种类全部注册 EVENT_KINDS；异常路径（Quota/429 在 `_try_finalize`/集成验收内抛出）均由 run_task 统一捕获收口，无漏记/重记（`_finalized` 缓存与 `"outcome" in outcome` 检查双保险）。

## 遗留 Open（设计决策点，不擅自改）

- **O1** `_finalize_run` 回填路径按 accepted 计数给 partial（degenerate/escalate/quota/轮次耗尽，未过集成门）。保守兜底 vs "无验证子集不自动 partial" 的严格读法，需设计裁定。
- **O2** Lead accept 一棵零 accepted 的树：outcome=failed 但 root 仍按 accepted-by-lead 封存为 accepted；autoclose 同情形 root 是 escalated。两路径 root 处置不对称（final 路由值兼容保留所致）。
- **O3** 登记表外需求的逐条 verdict 被 `_req_statuses` 丢弃；登记完整性复核只剩 integrated 总 verdict + gaps 文本承载。可增强（清单外 id 记 unknown 缺口）。
- **O4** >12000 散文缺陷不可见；ref 对验收方不可取回（Lead 无 fetch 通道）。后续可考虑给集成验收 Lead 接 PULL 式回查。
- **O5** 需求提取启发式边界：顶格编号/bullet、≤12 条、内容 7-207 字符。段落式要求不登记 → 覆盖门退化、集成验收退为整体核对（prompt 有"以原文为准"兜底）。
- **O6** `weakened` 校验被 `missing` 蕴含（冗余）。保留作门放松时的防线，或精简——风格决策。
