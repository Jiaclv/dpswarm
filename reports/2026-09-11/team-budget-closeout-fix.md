## 修复行为

1. **预算估算包含尚未提交的本轮消息。** 当前步骤的用户任务、环境上下文、技能目录与其他宿主钩子最后追加的消息一并参与请求额度计算；按步骤、信号和消息身份去重。系统消息按宿主实际结构计入；替换或追加方式在请求准备前不确定时取保守上界。原生 preparedCall、持久化 request/header 与最终发送请求保持同一个 maxTokens，未在发送阶段篡改已冻结请求。
2. **收尾校验读取实际请求里的系统消息。** 兼容旧单独 system 字段；只认可最后非空 system 角色文本，不把用户/工具/assistant 中的标记当作收尾指令。原有额度上限、最多两次收尾请求和收尾期间的工具/压缩限制保留。
3. **完全未执行的预算准入失败允许同任务重试。** 仅限 WORKER_TOKEN_RESERVATION_DENIED，所有已发布子会话必须有可信的持久化终态诊断、确认物理清理及控制面结算、无交付、调用/未知调用/活跃调用/已承诺 token/观察 token 全为 0。后续 attempt 用新 run_id，保留旧审计；状态和返回说明明确可再次 dpswarm_run。旧运行的延迟回调、重复结算与并发启动不能误改新运行。
4. 更正 dpswarm_rework 工具说明：默认固定 600,000 token / 28 次，已保存设置优先。没有调整用户的模型、预算设置或已有任务锁。

历史 `failed_takeover` 不自动改写为可重试。更新后重新发送任务会建立新的用户任务绑定；有实际执行、交付或不确定清理的失败仍保持原有接管/返工规则。
